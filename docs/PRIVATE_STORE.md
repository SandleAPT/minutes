# ⑨ 비공개 자료 저장소 — 무엇을 어떻게 넣는가

관련 코드: `assets/js/app/private.js`, `scripts/gas/private-store.gs`

## 왜 따로 있는가

공개 회의록 GAS는 **공개 토큰으로 읽힌다.** 토큰이 공개 HTML에 들어 있으므로 그쪽에 민감 자료를 넣으면 비공개가 아니다(`DATA.md` §8 참조). ⑨는 그것과 완전히 다른 웹앱으로, **읽기·쓰기 모두 서버에서 비밀번호를 검증**한다.

- 저장소 주소는 공개 코드에 없다. 이 기기 `localStorage.sandle_private_url`에만 있다.
- 키는 2단계: 열람용은 `list`·`get`, 수정용만 `save`·`delete`.
- 파일은 dataURL 문자열로 시트에 넣고, 45,000자씩 조각내 여러 행에 저장한다.
- **항목당 약 8MB가 한계.** dataURL은 원본의 약 1.37배가 된다.

원본과 그것을 읽어 정리한 메모는 **한 항목에 묶는다.** 따로 두면 나중에 어느 판독이 어느 원본에서 나왔는지 알 수 없다.

## 로컬 파일을 넣는 방법 (AI가 할 수 있다)

> **먼저 정정**: 2026-09-01에 "AI는 로컬 파일을 드라이브에 못 올린다"고 확인한 것은 **드라이브에 한해서만** 맞다. 그것을 "비공개 자료를 넣으려면 사용자가 드라이브에 올려야 한다"로 넓혀 말한 적이 있는데(2026-09-02) **틀렸다.** ⑨는 드라이브를 거치지 않는다.

1. 대상 폴더를 **localhost로만** 잠깐 여는 임시 서버를 띄운다. 외부에는 열지 않는다.
2. 회의록 앱 페이지에서 그 파일을 `fetch` → `FileReader.readAsDataURL`.
3. **같은 페이지 안에서** 저장소에 `save`를 부른다.
4. 서버를 닫는다.

### 왜 굳이 페이지 안에서 하는가

관리자 비밀번호가 그 페이지 `localStorage`에만 있고, **AI는 그 값을 꺼내 보면 안 된다.** 페이지 안에서 저장하면 비밀번호가 페이지 밖으로 나오지 않는다. 셸에서 직접 POST하려면 비밀번호를 평문으로 다뤄야 하므로 하지 않는다.

같은 이유로 `private.js`의 `api()`를 그대로 쓰면 안 될 때가 있다 — 키가 없으면 `prompt()`를 띄운다. 비밀번호 입력창은 **사용자만** 채운다. 읽기만 확인할 때는 저장된 키로 직접 `fetch`한다.

### 저장한 뒤에는 되읽어 대조한다

응답의 `ok`만 믿지 않는다. `get`으로 다시 읽어 **파일 이름·형식·dataURL 길이**와 메모 본문까지 맞는지 본다. 2026-09-02 4건 모두 이 방식으로 확인했다.

### 덮어쓸 때는 id를 유지한다

`save`는 같은 id의 행을 지우고 다시 넣는다. 고친 자료를 새 id로 올리면 옛 내용이 남아 어느 것이 최신인지 알 수 없게 된다.

### Windows에서 걸린 것

임시 서버 스크립트에 한글을 넣으면 안 된다. Windows PowerShell 5.1은 BOM 없는 `.ps1`을 ANSI로 읽어 한글이 깨지고 파서가 죽는다. 스크립트는 ASCII로 쓰고 폴더 경로는 인자로 넘긴다.

## 한계와 다음 단계

파일을 **시트 셀**에 넣는 방식이라 항목당 약 8MB가 끝이다. 지금 자료(최대 2.5MB)는 여유가 있지만, 스캔 묶음처럼 큰 것이 들어오면 Drive에 파일로 두고 `file_id`만 참조하는 구조로 바꿔야 한다(Apps Script에 `DriveApp` 액션 추가). **한도에 걸리는 자료가 실제로 생기면 그때 한다.**

Drive로 옮기더라도 링크를 공개(`anyone with the link`)로 두면 비밀번호 체계가 통째로 무력해진다. 파일은 비공개로 두고 Apps Script가 비밀번호 확인 후 내려주는 구조여야 한다.
