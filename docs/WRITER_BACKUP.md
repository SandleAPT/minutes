# 작성자 변경 백업

상태: 구현·fixture 검증 완료. 운영 Apps Script 배포 전이며 현재 운영 서버에서는 작동하지 않는다.

## 범위

작성자 비밀번호로 기존 회의의 안건을 수정·추가·삭제하고 저장할 때 변경 전 전체 회의록과 변경 예정 회의록을 별도 서버 시트에 기록한다. 관리자 비밀번호 작업은 제외한다. 백업 검증이 실패하면 원본 저장도 중단한다. 아직 저장하지 않은 브라우저 입력은 대상이 아니다. 후속 사용자 요청으로 새 회의 등록도 작성자에게 허용하며 새 등록 이력도 보관한다. 회의 자체 삭제·발행·기존 회의설정/명단 수정은 관리자 전용이다.

과거 공개 회의는 작성자 수정 대상에 포함되지 않는다. 일반 방문자가 보는 발행본은 작성자 저장으로 바뀌지 않는다. 백업에는 서버 JSON에 들어 있는 회의설정·명단·원문을 보존하지만 로컬 첨부파일 바이너리는 포함하지 않는다.

안건·발언 화면의 `＋ 새 회의 등록` 또는 상단 `＋ 새 회의록`을 사용한다. 기준 회의를 선택하고 새 회의의 날짜·정기/임시·시간·장소를 입력한다. 기준 회의의 기수·명단을 서버에서 이어받고 안건·출석은 빈 상태로 시작한다. 같은 등록 요청의 네트워크 재시도는 중복 회의를 만들지 않는다. 최초 기준 회의가 없다면 관리자가 명단을 갖춘 회의 1건을 먼저 등록해야 한다.

## 운영 서버 적용

1. 메인 Apps Script 프로젝트 (관리자 로컬 배포 기록 참조)에서 기존 `writer.gs`, `publication.gs`를 읽어 저장소 기준과 일치하는지 확인한다. 운영 파일을 별도로 보관한다. 다른 변경이 있으면 먼저 병합한다.
2. 이 변경안의 `scripts/gas/writer.gs`와 `scripts/gas/publication.gs`를 해당 파일에 적용한다. 운영 Code.gs와 스크립트 속성의 비밀번호·시트 ID는 바꾸지 않는다.
3. 배포 관리에서 기존 운영 배포의 연필 → 새 버전으로 갱신한다. 새 URL을 만들지 않는다. 보조 활성 배포가 있다면 같은 버전으로 갱신한다.
4. 관리자 인증 `writerBackupList` 요청이 빈 목록 또는 기존 목록을 반환하고, 작성자 인증에는 `admin_required`가 반환되는지 읽기 전용 확인한다.
5. 운영자가 별도 합성 회의를 등록한 뒤 작성자 키로 안건 수정·추가·삭제를 저장해 매번 이력을 확인한다. 사용자 실회의를 시험 수정하거나 시험 발행하지 않는다. `before`의 날짜·이름·전체 JSON과 원본을 대조한다.

6. 서버 검증 후 사이트의 `agenda-writer.js`, `core.js`, `index.html`(v462)와 포털 `index.html`(v462)를 함께 반영한다. 작성자 새 회의 등록→새 회의 선택→안건 저장 및 등록 재시도(중복 없음)를 합성 회의로 확인한다. 프론트엔드만 게시하면 authorCreate가 운영 서버에 없어 실패한다.

별도 시트 `minutes_writer_backups`는 최초 작성자 변경 시 자동 생성된다. 웹 조회는 관리자만 가능하며, 원래 Google 시트 공유 권한은 그대로 따른다. 파일을 GitHub에 올리는 것만으로 서버 기능이 활성화되지 않는다.

## 이력 조회·복원

인증정보는 코드/명령 기록에 넣지 않고 기존 관리자 세션의 메모리에서만 사용한다. 공개 POST 엔드포인트에 기존 token/adminKey와 아래 필드를 보낸다.

- `{action:'writerBackupList',id:<회의 ID>}`: 해당 회의의 최신 이력부터 메타데이터 조회. id 생략 시 전체.
- `{action:'writerBackupGet',backupId:<백업 ID>}`: `item.before` 원본과 `item.proposed` 변경 예정 상태 조회.

`proposed.updatedAt`은 기준 원본 시각이며 새 저장 완료 시각이 아니다. 백업은 원본 변경 전에 남기므로, 백업 후 원본 저장이 실패했다면 실행되지 않은 변경 시도도 남는다. 자동 재시도·중복 요청이 충돌로 거절되거나 변경이 없으면 새로운 이력을 남기지 않는다.

새 회의 등록 이력은 `operation:create`, `before:null`로 반환한다. 생성 전 존재한 회의가 없으므로 빈 상태를 기존 회의로 복원하지 않는다. 생성 시 사용한 회의 설정은 `proposed`에서 조회할 수 있다.

복원이 필요하면 현재 회의도 따로 보관하고 관리자 작업으로 `before`의 id/name/date/json을 그대로 `save`한다. 날짜를 빼지 않는다. 저장 후 원본과 json/name/date를 재조회 대조하며 date는 같은 날인지 확인한다. 공개 발행본은 자동 재발행하지 않는다. 자동 복원·이력 삭제 API는 추가하지 않는다.

## 재현

`node tests/publication.test.js` — 작성자 변경 전·후 전체 원본, 관리자 제외, 안건 추가·삭제, 무변경/충돌/입력오류 제외, 백업 쓰기·검증 실패 시 원본 불변, 조회 권한·공개본 보존 검증.

`for f in tests/*.test.js; do node "$f" || exit 1; done`

후속 새 회의 등록 기능으로 프론트엔드도 변경된다. 사이트 공통 버전·캐시 키는 v462 예정이며, Apps Script 서버는 별도의 새 배포 버전이 필요하다.
