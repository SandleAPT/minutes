> 공개 주소: https://sandleapt.github.io/minutes/ · 저장소: github.com/SandleAPT/minutes · 마지막 갱신: 2026-08-25 (v69)

## 1. 목적
- 산들마을 **입주자대표회의(입대의)**와 **임차인대표회의(임차)**의 회의록을 한곳에 쌓고, 입주민 누구나 **안건을 주제별·시간순으로** 찾아볼 수 있게 한다.
- 10년치(수백 건)가 쌓여도 느려지지 않고, 읽기 쉬워야 한다.
- 관리자(동대표)는 같은 화면에서 회의록을 **작성·저장**하고 Word/한글/PDF로 낸다.

## 3. 지키는 원칙
1. **공개 사이트** — 저장·삭제·이력 저장 등 **쓰기 동작은 항상 관리자 비밀번호**(서버 검증, 브라우저별 1회 입력·기억). ⑧ 안건·발언 입력 화면도 진입 전에 같은 서버 검증을 거친다. 공개 선거 현황에는 공고의 객관적 분포·결과만 두고, 특정 대상자의 자격·절차 점검은 비밀번호가 필요한 `절차 점검`에서만 보여 준다.
2. **업데이트마다 버전 +1** (`<title>`·사이드바 `vNN · 날짜`), 푸시 전에 **브라우저로 문법 확인**(node 없음; v49 사고 참고).
3. **회의록은 원문 충실** — 결과공고만 있으면 안건명+의결만, 표결 없으면 "참석자 전원 찬성 + 비고", 손글씨 판독 불명은 `?` 표시.
4. **요약은 회의 1건 = 글머리 1줄**(`YY.MM 정기:` 접두어), 맨 아래 `- 현재 상태:` 한 줄. 새 안건이 들어온 뒤 "요약 갱신해줘"로만 갱신(미반영 안건은 화면에 표시됨).
5. **명단은 회의록마다 스냅샷** + 변동 이력(취임·사퇴·선출, 임기 산입 여부)으로 "누가 언제 바뀌었는지"를 남긴다. 임기 회차(중임)는 전체 회의록 명단 색인으로 자동 계산.
6. **입대의와 임차는 같은 구조, 다른 색**(◆ 금색 / ◇ 청록), 기수 기간표도 따로(입대의 2년 주기 자동, 임차 `TENANT_TERMS` 수동).
7. 데이터 크기 한계: 시트 셀 **50,000자** — 큰 시스템 레코드는 조각 저장(`_p1.._pN`).
8. 문서 3종을 코드와 함께 관리: `docs/PLAN.md`(이 파일) · `docs/DATA.md`(데이터 규칙) · `CHANGELOG.md`(버전별 변경).

## 6. 작업 절차 (요약)
1. 자료(PDF/사진) 받기 → 이미지 변환 → 판독 → 레코드 JSON 작성 → 클라우드 저장(관리자 키) → `data.json` 재발행 트리거(필요 시) → 라이브 확인
2. 기능 변경 → 버전 +1 → 로컬 브라우저 확인 → 커밋/푸시 → 라이브 확인 → `CHANGELOG.md`·이 문서 갱신
3. 요약 갱신 → `TopicSummaries.stale()`로 대상 확인 → 새/변경 안건만 반영 → 저장 → 미반영 0 확인
